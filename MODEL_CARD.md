#### Description

`ctheodoris/Geneformer` hosts several checkpoints; this pipeline packages exactly one, `Geneformer-V2-104M`, pinned to revision `1f7fbae4e469a5f4f1af8c111a529cfe1b3829f5`. Geneformer (Theodoris et al., *Nature* 2023; Chen et al., bioRxiv 2024) is a transformer encoder for single-cell transcriptomes whose defining idea is its input representation rather than its architecture. A cell is presented as a **rank value encoding**: each gene's expression in that cell is normalised for library size and divided by that gene's median expression across the pretraining corpus, the genes are ranked by the result, and the ranked gene identifiers are the tokens. Ubiquitous housekeeping genes are scaled down; genes that are lowly expressed but expressed rarely move up. The pinned `config.json` names a 12-layer BERT encoder, hidden size 768, 12 attention heads, intermediate size 3072, absolute position embeddings, `max_position_embeddings` 4096 and a vocabulary of 20,275 gene tokens; the upstream README records V2 pretraining on ~104 million non-cancer human single-cell transcriptomes (Genecorpus-104M). At inference the model returns a contextual 768-dimensional hidden state per gene token; it produces a representation, and it is adapted by gradient training rather than by in-context conditioning. What this repository adds is the `GeneformerPipeline` class in `src/geneformer_single_cell_pipeline/pipeline.py`: manifest verification of the 6-file snapshot before any model library is imported (`verify_snapshot`), fresh-clone staging at the pinned revision only (`stage_missing_files`), a **restricted unpickler** that loads the three pinned gene dictionaries while refusing every global except the numpy scalar types they legitimately contain (`RestrictedUnpickler`, `load_gene_vocabulary`), a notebook-local implementation of the rank-value encoding that reports what it dropped and truncated (`rank_value_encode`), input and dataset validation with named ceilings (`validate_inputs`, `validate_dataset`), mean-pooled cell embeddings (`embed`), bounded gradient fine-tuning of a `BertForSequenceClassification` head plus the last *n* encoder layers (`adapt`), held-out classification metrics (`evaluate`), argmax classification with per-class scores (`classify`), and a safetensors adapter artifact whose manifest is verified before deserialization and which reloads against the pinned base and subfolder (`save_artifact`, `from_artifact`). The upstream `geneformer` Python package is **not** a dependency of this pipeline.

#### Intended Use and Limitations

###### Primary Intended Uses

Two tasks are exposed. **Cell representation:** input is 1 to `MAX_CELLS_PER_CALL = 32` cells, each a mapping from human Ensembl gene id (or an approved gene symbol) to a non-negative count; output is one 768-dimensional vector per cell (the mean of the last hidden state over the cell's tokens), suitable as features for a downstream model, for similarity search across a cell set, or for clustering. **Cell-state classification:** given a labelled dataset of `{id, counts, label}` records with 2 to 20 classes, the pipeline fine-tunes a classification head (optionally with the last encoder layers) and then predicts a class with per-class scores for new cells. Envisioned application domains are single-cell analysis workflows where a modest labelled set already exists — transferring cell-type or cell-state labels within a study, distinguishing a perturbed from a control population, triaging cells for manual review, and teaching or evaluating single-cell foundation-model transfer. In a larger system the pipeline is a feature extractor and a fine-tuning baseline whose output feeds expert review or a downstream model, not an autonomous cell annotation service.

###### Primary Intended Users

Intended users are computational biologists, bioinformaticians and machine-learning engineers working with single-cell RNA-seq, in research, internal enterprise, or the DIMER model workbench. The pipeline assumes its users understand that the pinned gene vocabulary is **human** and that non-human identifiers will not resolve; that cells from one donor, plate or sequencing run are not independent, so a random split leaks and a donor- or batch-level split is their responsibility (the pipeline cannot detect the grouping); that quality control — ambient RNA, doublets, dying cells, minimum gene detection — happens before this pipeline sees the counts and materially changes the ranking; that the softmax scores it returns are uncalibrated; and that a fine-tuned classifier is only as good as the labels supplied, which the pipeline cannot audit.

###### Out-of-scope use cases

1. **Capability boundary:** the pipeline exposes whole-cell embeddings and whole-cell classification only. It does not perform in-silico perturbation, gene classification or gene-network analysis, masked-gene prediction, multitask or continual learning, regression on a continuous target, or trajectory/pseudotime inference; it does not read `.h5ad`, `.loom`, `.mtx` or any other single-cell file format (its input is a mapping of gene identifier to count), and it does not load the V1-10M, V2-316M or cancer-tuned checkpoints in the same repository.
2. **Input boundary:** counts must be finite and non-negative; at least `MIN_DETECTED_GENES = 10` genes must be detected per cell **and** carry both a Geneformer token and a corpus median, or the cell is refused rather than ranked from nothing; at most `MAX_GENES_PER_CELL = 4094` ranked genes fit the 4,096-token input and the remainder is truncated at the low-rank tail and reported; at most 32 cells per call. A dataset needs at least 8 records, at least 3 per class, at most 2,000 records and at most 20 classes, with unique ids. Mouse and other non-human gene identifiers, protein or ATAC features, and spatial coordinates are not inputs.
3. **Decision boundary:** not for autonomous action on a predicted cell state — clinical or diagnostic interpretation, patient management, treatment selection, or any decision taken without a domain expert reviewing the evidence and without task-specific validation on data from the deployment's own tissue, protocol and batch structure. A predicted label is a hypothesis for a biologist to check, not a cell annotation of record.

#### Factors

###### Groups

The pipeline is human-centric in an indirect but real sense: its inputs are human cells, and every cell came from a person. The pipeline never sees donor identity, demographics or phenotype, so it cannot evaluate performance by any demographic group, and no such evaluation was performed here. The factors its behaviour does vary with are biological and technical: tissue and cell type, the donor's disease state, the sequencing protocol (10x 3'/5', Smart-seq, sample-multiplexing), sequencing depth and the resulting number of detected genes, dissociation and ambient-RNA levels, and — for the classifier — class balance and the donor/batch structure that the split does or does not respect. The upstream corpus (Genecorpus-104M, non-cancer human transcriptomes) is not audited by its authors or here for donor ancestry, sex, age or tissue balance, and single-cell atlases are known to over-represent some tissues, ancestries and healthy adult donors; representation quality is therefore uneven in a way this pipeline cannot measure. The downstream operator must stratify their own evaluation by the factors that matter — at minimum by donor and by batch, and by any demographic attribute their study records — and check that per-group accuracy is not hidden behind an aggregate number. Because the underlying material is human, a deployment that links cells back to identifiable donors inherits the full set of personal- and health-data obligations.

###### Instrumentation

The instrument is a single-cell RNA sequencing workflow, and its characteristics dominate everything downstream. Cells are dissociated from tissue, captured (droplet or plate), reverse-transcribed with UMIs or without, amplified, sequenced, and quantified by an alignment and counting pipeline; the pretraining corpus is the aggregate of many such workflows as deposited in public atlases. The properties that materially affect the data are capture efficiency and sequencing depth (which set how many genes are detected at all), the 3'/5' chemistry and gene annotation used for quantification, ambient RNA from lysed cells, doublet rate, and the dissociation stress response that some protocols induce. Rank-value encoding is deliberately robust to one of these — absolute depth largely cancels when genes are ranked — but not to the others: ambient contamination and doublets change *which* genes rank highly, which is precisely the signal the model reads. At inference this pipeline passes the caller's counts verbatim: no normalisation beyond the documented rank-value step, no quality-control filtering, no doublet detection, no ambient correction, no gene-annotation harmonisation. Defects in the operator's upstream pipeline reach the model unchanged, and the pipeline detects only the shape errors it validates (count validity, minimum detected and encodable genes, ceilings, duplicate ids, class coverage) plus the genes it could not resolve, which it reports rather than dropping silently. Labels are a second instrument: whether they come from marker-gene gating, reference-atlas transfer or experimental design, their error rate passes straight into the fine-tuned head.

###### Environment

Operating environment: Python 3.12 with `torch==2.14.0` (the venv build is `2.14.0+cu130`), `torchvision==0.29.0`, `torchaudio==2.11.0`, `transformers==4.57.6`, `huggingface-hub==0.36.2`, `safetensors==0.8.0`, `numpy==2.5.3` (`pyproject.toml`); the model loads to CPU and moves to `device`, which defaults to `cuda:0` when CUDA is visible and `cpu` otherwise. Only float32 is exercised — no quantisation, autocast or compiled kernels — although the upstream V2 work describes quantised variants that this pipeline does not use. The executed CPU run is recorded under "Runtime" (verify 0.3 s, dictionaries 0.1 s, load 8.8 s, 4-epoch adaptation on 36 cells 141.6 s, whole workflow 154.1 s on the reference machine). Memory and time scale with the number of ranked genes per cell times the batch size, because each batch is padded to its longest cell; a 32-cell batch of 4,094-gene cells is the worst case the ceilings allow and was not measured — the tutorial's cells rank about 348 genes each. Data environment: the model assumes human single-cell transcriptomes resembling the pretraining atlases, quantified against a standard Ensembl gene annotation. Its representations degrade, without any error, on non-human data (identifiers simply fail to resolve, which the validator reports), on bulk RNA-seq profiles, on cells with very few detected genes, on heavily ambient-contaminated or doublet-rich data, and on assays other than transcriptomics. For the classifier the load-bearing assumption is that evaluation cells are drawn from the same distribution as the training ones *and are not from the same donors or batches*: if they are, the reported metrics measure memorisation of a donor rather than generalisation, and the pipeline cannot detect this for the operator.

#### Metrics

###### Performance Measures

The pipeline reports, exactly as `metrics.classification_metrics` names them: `accuracy` (share of cells whose argmax class is correct), `macro_f1` (unweighted mean of per-class F1 over classes present in the split), `per_class` precision/recall/F1 with `support` and `predicted` counts, and `auroc` (area under the ROC curve; for two classes the positive class is the last entry of the class list, for more it is the macro one-vs-rest average, computed from the Mann-Whitney rank statistic with average ranks for ties). Accuracy alone is misleading on the imbalanced class distributions that are normal in single-cell data — a rare cell state can be ignored entirely while accuracy stays high — which is why macro-F1 and the per-class rows are returned with it; and both are threshold-dependent, which is why AUROC is returned too. The distinction is not academic here: the executed run's first schedule produced AUROC 1.0 with accuracy 0.5, an under-trained head whose ranking was already perfect while its decision boundary had not moved. Two baselines are reported with the same fields: `majority_baseline` (predict the most frequent training class) and, for binary tasks, `library_size_baseline` (one threshold on total counts per cell, fitted on the training split only) — library size is the first confounder to rule out in single-cell classification. The embedding stage reports **no** performance measure: it emits a 768-dimensional representation with no label, and the caller must supply a labelled downstream task, or a reference set with known relationships, before any quality claim about the embeddings can be made. The executed CPU run recorded under "Runtime" is sample-sanity evidence on synthetic cells, not a benchmark; no upstream benchmark number is reproduced in this repository.

###### Decision thresholds

The default decision rule for `classify` is an `argmax` over `softmax(logits)` — an implicit threshold, and the only one the pipeline applies. No tuned operating point ships: the pipeline emits the full per-class score dictionary alongside the argmax label so that a deployment can apply its own rule, and calibrating that rule is the operator's job. Choose it from the asymmetric cost in the setting: for flagging a rare cell state for expert review, a low threshold with a human reading the borderline band is usually right; for populating an annotation column that others will treat as fact, a high threshold plus an explicit "unassigned" outcome is safer than forcing every cell into a class. The thresholds that *were* set during development are input-contract limits, not decision thresholds: `MAX_INPUT_TOKENS = 4096` and therefore `MAX_GENES_PER_CELL = 4094` (the checkpoint's position-embedding limit; beyond it the low-rank tail is truncated and the truncation is reported), `MIN_DETECTED_GENES = 10` (below which a ranking is not meaningful and the cell is refused), `MAX_CELLS_PER_CALL = 32`, at least 8 dataset records and 3 per class, at most 2,000 records and 20 classes. No accuracy acceptance threshold was set, because this repository ships no task for which one would be meaningful.

###### Approaches to uncertainty and variability

Reported metrics come from a **single seeded holdout**: `split_dataset` stratifies by class with an explicit seed (default 42) into train/validation/test, and `evaluate` scores one split once. No cross-validation, bootstrap or repeated-run averaging is performed, and no standard deviation or confidence interval is reported — with the 16-cell tutorial test split, any dispersion estimate would be dominated by the split itself. A caller who needs one repeats the workflow over several seeds, or supplies enough labelled cells for k-fold with donor-aware folds, and owns that design. Sources of run-to-run variability inside the pipeline: the split (seeded), shuffling of training batches (seeded via `random.seed`), classification-head and pooler initialisation and dropout (seeded via `torch.manual_seed`/`torch.cuda.manual_seed_all`), and non-deterministic GPU kernel selection and float accumulation order, which are **not** controlled by a seed and can move scores in their low-order digits — enough to flip a cell whose two class scores are close. Rank ties are broken deterministically by gene id, so the encoding itself is stable. The forward pass runs under `torch.no_grad()` in `eval()` mode, so inference on a fixed device and dtype is otherwise deterministic. The per-class scores are softmax outputs of a head trained on a few dozen cells; they are **not calibrated probabilities**, and a caller who needs calibrated confidence must fit a calibrator on held-out labelled cells of their own. Embeddings carry no uncertainty estimate of any kind.

#### Ethical considerations and biases

###### Data

Upstream discloses the pretraining data as Genecorpus-104M for V2 — approximately 104 million non-cancer human single-cell transcriptomes drawn from public sources, with V1 trained on the ~30 million-cell Genecorpus-30M and cells of high mutational burden (malignant and immortalised lines) excluded — and does not publish a per-study, per-donor or demographic breakdown; that is where upstream disclosure ends, and this repository adds none. The underlying material is human tissue from consented donors in the source studies, so the corpus is derived from personal biological data even though the model stores no donor identity: whether any individual entry is traceable to a person is not established either way by the upstream authors — it is unknown, not ruled out. Single-cell transcriptomes are themselves potentially identifying in combination with genotype information, which is a reason for care with the data an operator supplies rather than with the released weights. This repository distributes code, tests and documentation; it does **not** vendor the weights or the gene dictionaries in Git (`model.safetensors` and the three `.pkl` files are git-ignored and reproduced from the pinned revision by `stage_missing_files`, then digest-verified), and it ships no cell dataset — the tutorial data is generated in code from a seeded random process over real gene identifiers and contains no measured cell. The operator owns the audit of whatever they submit: patient-derived or clinical-trial cells may be health data under their jurisdiction's law, unpublished atlases may be confidential or third-party proprietary, and consent for secondary use may not extend to the analysis they have in mind. The pipeline performs none of these checks and transmits nothing — inference is local — but it also does not stop anything.

###### Human Life

This pipeline is not intended for decisions in health, safety, criminal justice, employment, credit, or housing, and it has not been validated or certified for any of them by anyone. No clinical validation, no regulatory clearance, no external review board and no testing with any specific group has taken place; the only evidence in this repository is the offline unit suite (42 tests) and one executed CPU run on synthetic data recorded under "Runtime". Use in a sensitive domain is nevertheless foreseeable — single-cell classifiers are applied to tumour microenvironment characterisation, immune profiling of patients, and biomarker discovery that feeds trial design — and would be admissible only with a domain expert reviewing every consequential output, independent validation on cells representative of the deployment with donor-aware splits, evidence that the labels themselves are fit for the purpose, and whatever clinical-laboratory and regulatory clearance the domain requires. A predicted cell state from this pipeline is a hypothesis to test at the bench, never a result to act on.

###### Mitigations

1. **Supply-chain integrity:** `MODEL_ID`, the 40-hex `MODEL_REVISION` and `MODEL_SUBFOLDER` are module constants; `verify_snapshot()` checks `modelId`, `revision`, and the byte size and SHA-256 of all 6 manifest entries before any load and raises on the first mismatch (tests flip a digit, change the revision and delete a file and assert each raises; the executed run verified all 6 entries including the 417,571,156-byte checkpoint). `stage_missing_files()` fetches only manifest-listed files absent on disk, only at `MODEL_REVISION`, only when `allow_download=True`, and refuses a manifest naming another model. The loader reads the verified directory with `local_files_only=True`, `trust_remote_code=False` and `use_safetensors=True`; the upstream `training_args.bin` (a torch pickle) is deliberately not staged. `.gitattributes` carries `weights/** -text` so a Windows checkout cannot corrupt a digest through line-ending conversion.
2. **Deserialization boundary for the gene dictionaries:** Geneformer's tokenizer is three Python pickles, which are code-capable by construction. They are digest-verified as part of the snapshot, and then loaded through `RestrictedUnpickler`, whose `find_class` refuses every global except `numpy.core.multiarray.scalar` / `numpy._core.multiarray.scalar`, `numpy.dtype` and the concrete `numpy.dtypes.*DType` classes that the median dictionary legitimately contains; anything else raises `UnpicklingError` naming the refused symbol. A test pickles a callable and asserts the refusal, and the executed smoke refused `nt.getcwd`. The loaded dictionaries are then shape-checked: the token dictionary must hold exactly `VOCAB_SIZE = 20275` entries and all four special tokens, or loading fails.
3. **Artifact integrity:** the exported adapter is safetensors, not a pickle, and `load_artifact` checks the artifact format string, the recorded base model id, revision **and subfolder** (the repository hosts several checkpoints, so the subfolder is part of the identity), the class list, and the size and SHA-256 of every listed file **before** deserialising, then refuses any tensor name the base architecture does not have.
4. **Input integrity:** `embed`, `classify` and `validate_inputs` route through one checker, so their acceptance criteria cannot diverge; it rejects non-mapping cells, empty cells, non-numeric, negative, NaN or infinite counts, cells with fewer than 10 detected genes, too many cells, and id lists that are the wrong length or not unique. `rank_value_encode` refuses a cell in which no gene resolves, and otherwise reports unknown genes, genes without a corpus median, and truncated low-rank genes instead of dropping them silently. `validate_dataset` additionally rejects missing columns, duplicate ids, fewer than 2 or more than 20 classes, any class with fewer than 3 records, and — when given the vocabulary — cells with fewer than 10 *encodable* genes, which is the error a user gets for non-human identifiers.
5. **Import boundary:** verification, dictionary loading and validation run before `torch`, `transformers` or `safetensors` are imported (fleet RTM-001); `tests/test_import_boundary.py` fails if a rejected request reaches a model library.
6. **Statistical mitigations:** `split_dataset` stratifies by class so every split keeps the class proportions; no preprocessing state is fitted, because the encoding depends only on the pinned corpus medians (there is nothing to leak from the training split); validation metrics are used for monitoring only and the final epoch is kept rather than the best; and two trivial baselines are computed on the same split so a reported number always has a floor to be read against.
7. **Reproducibility:** every runtime dependency is pinned with `==`; splits, shuffling and initialisation take explicit seeds; rank ties break deterministically by gene id; every result carries `model_id` and `model_revision`; the adaptation record carries the full hyperparameter set and the trainable-parameter names and counts; `load_warnings` preserves whatever the libraries warned at load.
8. **Refusals:** in-silico perturbation, gene classification, masked-gene prediction, residue-level outputs, regression targets, single-cell file-format parsing, cells past the input window, and remote code are deliberately not exposed; full-parameter fine-tuning is bounded by the `trainable_layers` parameter (0..12) rather than being the default.

###### Risks and harms

1. **Donor or batch leakage inflating every metric:** the pipeline's random stratified split assumes independent cells, and cells from one donor are anything but. Related cells on both sides of the split turn memorisation of a donor's expression profile into apparent generalisation; the operator bears the harm as a model that fails on the next patient after passing its own evaluation. Likelihood is high on real data assembled per-donor, and the pipeline gives no warning — `split_dataset` documents the assumption, it cannot check it.
2. **Quality-control artefacts read as biology:** ambient RNA, doublets and stressed cells change which genes rank highly, so a classifier can learn "this batch was dissociated harshly" and report it as a cell state. Harm falls on the research programme: a confident, reproducible, wrong conclusion.
3. **Species and annotation mismatch:** the vocabulary is human and tied to an Ensembl annotation. Non-human identifiers are refused outright, which is safe, but a *partially* matching annotation (an older Ensembl release, symbol-based input with ambiguous aliases) resolves some genes and silently omits others, shifting the ranking. The pipeline reports the counts of unresolved genes; a user who does not read them can lose a third of a cell's transcriptome without noticing.
4. **Label error propagating silently:** the head learns whatever the supplied labels encode, including annotations transferred from a reference atlas that were wrong for this tissue. The resulting model reproduces that error at scale and the metrics, computed against the same labels, look fine.
5. **Uncalibrated scores read as probabilities:** a softmax score of 0.86 from a head trained on a few dozen cells is a ranking, not an 86 % chance. A downstream system that thresholds it as a probability will mis-state its own error rate.
6. **Automation bias in annotation:** model-predicted cell labels deposited into shared datasets or publications without a marker become training data and prior knowledge for the next study, entrenching the corpus's existing biases. The harm is diffuse and slow and falls on the field rather than on any one decision.
7. **Sensitive input handled without an audit:** the pipeline will happily encode patient-derived cells; it performs no check and the operator may not realise one was needed. Inference is local and transmits nothing, which bounds the exposure but does not discharge the obligation.

###### Use cases

The pipeline must not be used to infer, from a person's cells, health status, disease risk, ancestry or any other personal characteristic used to make decisions about them — in employment, insurance, credit, education, immigration or healthcare access — or to re-identify donors by combining single-cell profiles with genotype or other reference data. It must not be used to produce clinical or diagnostic outputs presented to patients or clinicians as validated, nor to deposit model-predicted cell annotations into public datasets or publications without marking them as model-predicted, which would pollute the atlases that future models train on. It must not be used to process cells the operator has no right to process — patient material outside the scope of its consent, confidential or third-party proprietary atlases — or in any way that breaches the Apache-2.0 terms of the upstream weights or the DIMER deployment terms. These prohibitions hold even where the model would produce an accurate answer.

## Input/output contract

- `GeneformerPipeline.from_pretrained(device=None, weights_dir=None, allow_download=False)`: stages and verifies the snapshot, loads the three gene dictionaries through `RestrictedUnpickler`, then loads `BertModel` (no pooling layer) from `<weights_dir>/Geneformer-V2-104M` with `local_files_only=True`, `trust_remote_code=False`, `use_safetensors=True`; `device` defaults to `cuda:0` when visible, else `cpu`.
- `rank_value_encode(counts, vocabulary, *, target_sum=10000.0, max_genes=4094) -> dict` with `tokens`, `ranked_gene_ids`, `n_detected`, `n_encoded`, `n_kept`, `n_truncated`, `unknown_genes`, `genes_without_median`, `library_size`.
- `embed(cells, *, names=None) -> dict` with `ids`, `embeddings` (one 768-float vector per cell), `dimension`, `pooling`, `unit`, `tokens_kept`, `genes_truncated`, `n_cells`, `model_id`, `model_revision`.
- `adapt(train_records, val_records=None, *, classes=None, epochs=4, learning_rate=2e-4, batch_size=4, trainable_layers=2, weight_decay=0.01, seed=42) -> dict`: bounded AdamW fine-tuning; returns the method description, class list, hyperparameters, trainable/total parameter counts, trainable parameter names, split sizes, the selection rule and the per-epoch history.
- `evaluate(records) -> dict`: `n`, `accuracy`, `macro_f1`, `per_class`, `classes`, `decision_rule`, `auroc`, `auroc_definition`.
- `classify(cells, *, names=None) -> dict` with `predictions` (each `{id, tokens_kept, label, score, scores}`), `classes`, `decision_rule`, `n_cells`, `model_id`, `model_revision`, `adaptation`.
- `save_artifact(output_dir, metadata=None) -> Path` writes `adapter.safetensors` + `manifest.json` (format, base model id/revision/subfolder/licence, class order, file sizes and SHA-256, tensor names, adaptation record); `from_artifact(artifact_dir, ...)` / `load_artifact(...)` verify all of that before deserialising.
- `validate_inputs(cells, vocabulary, *, names=None)` and `validate_dataset(records, *, vocabulary=None, classes=None, ...)` return the input and dataset manifests; both raise exactly what the execution path would raise.
- Constants: `MAX_INPUT_TOKENS = 4096`, `MAX_GENES_PER_CELL = 4094`, `MAX_CELLS_PER_CALL = 32`, `MIN_DETECTED_GENES = 10`, `HIDDEN_SIZE = 768`, `VOCAB_SIZE = 20275`, `MIN_RECORDS = 8`, `MIN_RECORDS_PER_CLASS = 3`, `MAX_RECORDS = 2000`, `MAX_CLASSES = 20`, `ARTIFACT_FORMAT = "org.valcorza.geneformer-single-cell.adapter.v1"`.
